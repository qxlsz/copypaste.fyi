# RSA-260 and this site

In September 2026, [RSA-260](https://en.wikipedia.org/wiki/RSA_numbers) was factored. That number is 260 decimal digits, about 862 bits. Factoring means writing it as a product of two primes. Headlines called that "RSA divisible."

It does not apply to copypaste.fyi.

## What RSA-260 is

RSA challenge numbers are homework for factoring algorithms. They are much smaller than keys used on the public internet. Common TLS still uses 2048-bit or 3072-bit RSA when it uses RSA at all. NIST is moving those systems toward ML-KEM (FIPS 203) because a large quantum computer would break RSA and ECC, not because RSA-260 fell.

An 862-bit record is not a break of 2048-bit RSA. Cost still grows steeply with bit length.

## What this site uses

Paste encryption here is never RSA. Optional algorithms:

- AES-256-GCM
- ChaCha20-Poly1305
- XChaCha20-Poly1305
- ML-KEM-768 plus AES-256-GCM (`kyber_hybrid_aes256_gcm`)

Those are authenticated symmetric ciphers, plus one lattice KEM. Factoring an integer does not recover an AES key or an ML-KEM secret.

Encryption is server-side. TLS still carries the key to the API. This is not end-to-end.

## What we reject

An encryption key that looks like an RSA private key PEM (`BEGIN RSA PRIVATE KEY`, `BEGIN RSA PUBLIC KEY`) is rejected. Do not paste RSA material into the key field. Use the generated 256-bit secret, or the ML-KEM hybrid mode.
